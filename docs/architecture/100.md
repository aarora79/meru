# Meru architecture, level 100: the big picture

*Meru* (मेरु) is a personal AI assistant that runs on a machine you control. It
answers questions from your notes and files, remembers what matters about you, and
uses tools such as web search, Gmail, your calendar and your Obsidian notes. The models run on your own
machine, so no prompt goes to an AI company.

> **Why "Meru"?** In some Eastern traditions, Meru is the cosmic mountain that the
> sun, moon and stars turn around. This assistant takes the name because it works the same way: it stays in
> one place, on your machine, and your notes, tools and daily routine turn around it.

This page covers the main parts in a few minutes. [Level 200](200.md) explains how
each part works, and [level 300](../../ARCHITECTURE.md) is the full design.

## The parts

![Diagram of Meru's parts. A dashed line marks your machine. Inside it, you type into meru or meru-desktop, which passes the question to merud. merud holds the scheduler, the agent loop and dispatch. The agent loop uses the local models in Ollama, your data and skills, and dispatch reaches other agents over A2A and tools over MCP. An optional Grafana dashboard runs on the same machine. Only the tools you allow reach internet services outside the line.](img/100-parts.png)

*Figure 1. Everything inside the dashed line runs on your machine: the models, your data and the assistant itself. Only the tools you allow reach the internet, and each call goes through `dispatch` first.*

- **Built in Go.** Meru is two small programs: `meru`, which you type questions into,
  and `merud`, which runs in the background and does the work. Go builds them into
  single files that run on macOS, Linux and Windows with nothing else to install.
  Compared with Python, that means a smaller footprint, easier installs, and room to
  run many Merus on one server.
- **A desktop app.** `meru-desktop` puts the same conversation in a window: past
  chats down the left, the answer in the middle with the files it used, and a
  panel that shows which tools ran, what Meru remembered and who the tools
  contacted. A switch picks where Meru looks: your files, your mail and calendar,
  the web, or nothing at all. Drop a file on the window, or pick one from any
  folder, and Meru reads a copy of it with your question. It asks before a risky
  tool call with a card inside the answer. Its Library turns each tool off, on, or on-after-asking, and picks
  the folders Meru reads; a Setup screen walks a new user through it. Like `meru`
  it only talks to `merud`, which makes every change. It runs on macOS for now.
- **Local models.** Ollama, a free program, runs open-weight models, models whose
  files anyone can download, on your machine. The default `lite` setup needs about 2
  GB of downloads and runs on most computers; the `full` setup uses a bigger model
  for better answers and needs a stronger machine. `merud` keeps the models loaded,
  so answers start fast. The desktop app lists the three answer models we tried,
  with the commands that download them, and switches between them without a
  restart. You can also name sets of models in the config file, switch between
  them from the chat with `/model`, and compare how each one did with `/usage by
  model`.
- **Your files.** You choose folders to index, such as your notes or documents. Meru
  indexes nothing until you list one, skips secret files such as `.env`, and keeps
  the index current as you edit. It searches your files by keyword and by meaning,
  and names the file behind each answer. A question for the web or for one of your
  tools, such as your calendar, skips that search. Email and calendar stay with their tools
  and never enter the index.
- **Memory.** Meru saves what it learns about you as small Markdown files (plain text
  you can open in any editor), sorted into folders such as `me/`, `preferences/` and
  `projects/`. You can read, edit or delete any of them. It also writes a short
  summary of each conversation, so it can recall what you discussed last week.
- **Your chats.** Each conversation is one plain text file under `~/.meru/sessions`,
  with one line per question, answer and tool call, in a format called JSON Lines.
  You can read, back up or delete these files. They are the record: Meru's search
  database is rebuilt from them and your folders, and Meru keeps no copy anywhere
  else.
- **Skills.** A skill is a Markdown file of instructions for one kind of task, such
  as writing a report or explaining a topic. Meru ships with four (`writing`,
  `explainer`, `web-research` and `file-research`), loads a skill only when a question needs it, and
  picks up any skill you add. One line in the config file turns a skill off. A
  skill can bring the tools it uses, such as web search, but only ones you have
  turned on.
- **Limits.** A question gets 5 minutes and a capped length of answer. When Meru
  can't answer inside them, it says sorry instead of going quiet.
- **Honest about what it did.** Meru tells the model what its own tools can
  change, and never to claim an action no tool took. When an answer still says
  "Done" or "I've moved it" and no tool ran, Meru adds a note under it: nothing
  changed on your computer. Asked which model it is, the model calls a tool
  that reads the answer from Meru's own settings, where it would otherwise
  guess from its training.
- **Web search.** Meru searches the web through SearXNG, a search engine you run on
  your own machine. It needs no account and no key. Your search words go out to
  the search engines SearXNG asks; your question and your files don't. Meru can
  also read a whole public web page, or download a file, when the model asks. It
  asks you first before it opens a web address that neither a search nor you gave
  it, so the model can't send your data out hidden in an address. One setting
  turns page reading off. When you ask for the web, paste a link, or name
  something your files don't mention, Meru searches before the model answers,
  so the model reads what the web says about the thing you named instead of
  guessing from its training. Later questions in the chat remember what the
  web said.
- **Tools and other agents.** Meru uses tools through MCP (Model Context Protocol),
  an open standard many services already support: Gmail and Google Calendar, your
  Obsidian notes. It can also hand a task to another agent over A2A
  (Agent2Agent). Tools start switched off; you turn on the ones you want, and Meru
  asks you before any tool call that sends, deletes or changes something. To let it
  run a program on your machine, such as `git log` or GitHub's `gh`, you write
  the whole command in the config file and the model fills in only the blanks,
  such as which folder; no shell runs it. The config file carries read-only
  GitHub commands, switched off, and `gh` keeps its own login, so Meru never
  holds your GitHub token. `meru setup` offers two starter tools (Google and
  Obsidian) and adds the ones you pick. Meru starts most tools itself.
  You start the Google one yourself, and Meru connects to it. When a tool stops,
  Meru leaves it stopped and tries it once more when your next question needs
  tools. That question also asks each running tool what it offers, so a tool you
  restart with new features offers them on that question. `meru mcp` shows which tools are
  connected. API keys stay in a file
  only you can read, and never pass through the model.
- **Observability.** Meru records how long each step takes, how many words the model
  read and wrote, and which tools it called. With the optional dashboard (Grafana)
  running on your machine, you can see why an answer was slow or which tool failed.
  Meru takes these measurements with OpenTelemetry, an open standard for them, and
  sends them only to a program on your own computer, and only if you run one. Your
  questions and Meru's answers stay out of them unless you turn that on.

## What happens when you ask

![Sequence diagram with five participants: you, Meru, your files and memory, the local model and a tool. Meru looks up related notes and memories and sends them with your question to the model. When the model asks for a tool, Meru asks you first if the call changes something, then calls the tool and hands the result to the model. Meru streams the answer to you word by word, with sources.](img/100-ask.png)

*Figure 2. The model never calls a tool itself. It tells Meru what it needs, and Meru makes the call, after asking you if the call would change something.*

Most questions skip the tool steps. When the model needs live information or an
action, Meru calls the tool, and it only stops to ask you when the call would change
something. The answer appears word by word as the model writes it.

## What Meru won't do

- Send your questions to a cloud AI model. The code has no way to do it.
- Send its measurements (telemetry) or crash reports off your machine, or check for
  updates. It measures itself, but that data stays on your machine.
- Turn on a tool you haven't allowed, or run a risky one without asking you.
- Run a command line the model wrote. It runs only commands you declared.

Every tool call Meru makes is written to a log you can read with `meru log`.
