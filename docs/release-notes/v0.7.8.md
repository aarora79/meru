# Release v0.7.8 - Web search keeps its container under Podman

**November 2026**

With Podman, Meru now starts its stopped SearXNG container again instead of deleting it and making a new one. A new test runs web search's container under Docker and under Podman, and the repository gains a made-up Obsidian vault for trying Meru without your own files.

---

## Upgrading from v0.7.7

### Breaking changes

There are no breaking changes in this release. Config, transcripts and `meru.db` don't change, the socket protocol is the same, and the daily report stays at version 2.

### New config keys

None.

### Upgrade instructions

**The one-line installer on a Mac.** Run it again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and run "Install Meru.app". It leaves your config and memories alone.

**Linux.** Run `install-linux.sh` again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install-linux.sh | bash
```

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.7.8
go install ./cmd/merud ./cmd/meru
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # Linux: systemctl --user restart merud
```

Then, on a Mac that reads Apple Notes: macOS drops the Full Disk Access grant
when the `merud` binary changes. In System Settings, open Privacy & Security,
Full Disk Access, and turn `merud` off and on again.

## Bug fixes

- With Podman, `merud` took its own SearXNG container for one of another image, so each time it started the container again, after a restart of the computer or a failed check, it deleted it and ran a new one. Podman names the pinned image without its tag; `merud` now matches the image by its digest and runs `podman start` (#265)

---

## What's new

### Tests

- `TestIntegrationContainer` runs the real web search container under Docker and under Podman, each alone: it pulls the pinned image, starts the container, runs a search, stops it and checks Meru starts the same one again. It is opt-in, with `go test -tags integration -run TestIntegrationContainer -v ./internal/connectors/` (#265)
- `testdata/vault/` holds a made-up Obsidian vault, with notes, a timesheet and PDFs, so you can try Meru's notes, files and tables without your own (#258, #264)

### The usage collector

- The public totals page at <https://meru-report.meru-workers.workers.dev/> draws the counts as charts: active and new installs over time, and this week's installs by version, system, chip and model set, with the numbers in tables beneath. What Meru sends doesn't change (#263)
