# Release v0.4.13 - Image Search, and a New Search Model

**October 2026**

Meru now finds the pictures in your folders: ask in words, or attach an image and
ask for ones like it. Both profiles search with a new model,
`embeddinggemma-2:440m`, which reads text and images into one index. The first
start after the upgrade embeds your files again.

---

## Upgrading from v0.4.12

### Breaking changes

There are no breaking changes to your chats or memories. Four things need care:

**1. Meru needs Ollama 0.40.5 or later.** Older versions can't pull or run the new
search model. `merud`, `meru setup`, the Mac installer and `install.sh` each check
the version and stop with a line that says to update. Update first:

```sh
brew upgrade ollama     # or download the app from ollama.com/download
ollama --version
```

**2. The first start embeds every file again.** The default search model changed
from `nomic-embed-text` (`lite`) and `qwen3-embedding:0.6b` (`full`) to
`embeddinggemma-2:440m`, a 713 MB download. Vectors from two models can't be
compared, so `merud` drops the old ones and embeds your files again in the
background. Keyword search covers the files it hasn't reached yet, and
`meru index -status` shows how far it has got. On an M4 Max, an index of 43,000
chunks took about 25 minutes. A restart part-way through picks up where it stopped.

If your `config.toml` names an embedding model, such as
`embed = "nomic-embed-text"` under `[models]`, Meru keeps it and indexes no
images. Set `embed = ""` to take the new default.

**3. Images go into the index.** The next scan embeds the PNG, JPEG, GIF and WebP
files in your `[index] folders`, up to 20 MB each, through Ollama on this
machine. A folder of photos adds to the first scan's time. Set `images = false`
under `[index]` to leave them out.

**4. Turn on `search_images` if your config lists its tools.** Most configs
written by `meru setup` or the installer list every built-in tool under
`[builtin] tools`, and that list doesn't grow by itself. Add `"search_images"`
to it and restart `merud`, or the model can't search images by name. An attached
image still finds ones like it without the tool.

### New config keys

| Key | Default | What it does |
|-----|---------|--------------|
| `[index] images` | `true` | Index the PNG, JPEG, GIF and WebP files in the `[index] folders`, so a question can find a picture and an attached image can find ones like it. `false` leaves them out, and the next scan drops them. |

A `config.toml` from v0.4.12 loads as it is, with images on. One new value goes
in an old key: `search_images` in `[builtin] tools`.

### Upgrade instructions

**The one-line installer.** Run it again; it keeps your `config.toml`, and stops
first if Ollama is too old:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and open "Install Meru.app". The first time, macOS refuses because
Apple hasn't checked Meru: click Done, then Open Anyway in System Settings,
Privacy & Security. The installer leaves your config and memories alone, and
pulls the new search model.

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.4.13
go install ./cmd/merud ./cmd/meru
make desktop-app && ditto bin/Meru.app /Applications/Meru.app
ollama pull embeddinggemma-2:440m
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # or: pkill merud; merud &
```

## Major features

### Find an image by what it shows

Ask in words, in the desktop app, `meru chat` or `meru`: "do I have a photo of
the garden beds?" The search model puts text and pictures in one space, so a
phone photo named `20250412_093015.jpg` can match "garden beds" by what it
shows.

- File search returns at most two images beside the text it finds, so pictures
  don't crowd out your notes.
- The new `search_images` tool searches images alone, by words or by the path of
  a picture in your folders or `~/meru-output/uploads`, under the same rules as
  `read_file`.
- Image results show under the answer with a small preview in the desktop app,
  and as `[1] ~/Documents/img/shot.png (image)` in the terminal.

[PR #118](https://github.com/aarora79/meru/pull/118),
[PR #119](https://github.com/aarora79/meru/pull/119)

### Find images like this one

Attach a picture in the desktop app, with the attach button or by dragging it in,
or in `meru chat` with `/attach`, and ask "find images like this". From a
terminal, `meru -image ~/Desktop/shot.png "find images like this"`; `-image`
works with `meru run --json` too.

- Every turn with an attached image searches for the eight images most like it
  before the model answers.
- An answer model that can look at pictures sees your image and the list, and
  says which fit.
- With one that can't, such as MiniCPM5-2B, Meru answers with the list itself
  and asks no model.

[PR #119](https://github.com/aarora79/meru/pull/119)

### One search model for text and images

`embeddinggemma-2:440m` replaces `nomic-embed-text` and `qwen3-embedding:0.6b`
on both profiles.

- `Embed` now takes text, an image, or both, and adds the model's own query and
  document prefixes, which EmbeddingGemma needs to rank well.
- Keyword search drops filler words such as "the", "show" and "please" when a
  question has other words, so "show me the garden plan" matches on "garden
  plan".
- `meru index -status`, the header in `meru chat` and the desktop app's Files
  row show "re-indexing X of Y" while the new model catches up.

[PR #116](https://github.com/aarora79/meru/pull/116),
[PR #117](https://github.com/aarora79/meru/pull/117)

## Bug fixes

- A re-embed stopped by a restart started over and embedded the finished files
  again; it now picks up where it stopped (#119).
- A model that could see an attached image missed the list of similar images in
  its prompt and offered a web search; the list now says Meru ran the search
  already (#119).
