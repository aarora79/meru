# Release v0.4.17 - Meru Reads Your Apple Notes

**October 2026**

On a Mac, Meru now searches, lists and reads the notes in the Notes app. It
reads the Notes app's own database each time you ask, so a note you wrote a
minute ago shows up, and it never changes a note. The Mac installer has a new
step that walks you through the one grant macOS needs.

---

## Upgrading from v0.4.16

### Breaking changes

There are no breaking changes in this release.

Two things need you once:

- **If your `config.toml` lists `[builtin] tools`**, which every config the
  installer or `meru setup` wrote does, add `"search_notes"`, `"list_notes"`
  and `"read_note"` to that list and restart `merud`. A list doesn't grow by
  itself. The Mac installer's new Apple Notes step adds them for you.
- **Give `merud` Full Disk Access** in System Settings, Privacy & Security,
  Full Disk Access. macOS never asks for it. Until you turn it on, a question
  about your notes answers with these steps.

### New config keys

None. `[builtin] tools` in the template gains the three notes tools.

### Upgrade instructions

**The one-line installer.** Run it again; it keeps your `config.toml`:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and open "Install Meru.app". The first time, macOS refuses because
Apple hasn't checked Meru: click Done, then Open Anyway in System Settings,
Privacy & Security. The installer leaves your config and memories alone, and
its Apple Notes step turns the notes tools on.

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.4.17
go install ./cmd/merud ./cmd/meru
make desktop-app && ditto bin/Meru.app /Applications/Meru.app
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # or: pkill merud; merud &
```

Then give the new `merud` Full Disk Access. Meru isn't signed by a registered
developer, so macOS ties the grant to one build: after every update, turn
`merud`'s switch in the Full Disk Access list off and on again.

## Major features

### Apple Notes, live and read-only

Three new built-in tools read the Notes app's database, `NoteStore.sqlite`:

- `search_notes` finds the notes that hold every word you ask for, in the
  title or the text. Title matches come first, newest first, each with a
  snippet.
- `list_notes` lists your Notes folders with their note counts and the newest
  notes, or one folder's notes.
- `read_note` reads one note in full, 12,000 characters at a time.

Ask by name, such as "search my Apple Notes for the garden plan" or "what's in
the Notes app about Lisbon?", and Meru offers the tools. "My notes" alone may
mean your indexed folders or an Obsidian vault.

- Each call opens the database read-only and closes it. Meru keeps no copy and
  no index, so an answer shows your notes as they are now.
- Meru leaves out deleted notes and Recently Deleted, never opens a locked
  note, and doesn't read attachments or drawings. Search matches words, not
  meaning.
- The tools only read, so they run without asking. What they return goes only
  to the local model.
- The Settings screen and `merud`'s log say when `merud` can't read the notes
  yet.

Meru reads the database itself, in Go, with no extra program. An npm server
tried first kept its own index, which missed a new note for more than six
minutes.

### An Apple Notes step in the Mac installer

The installer now has eleven steps. The new one, after Obsidian notes, turns
on the three notes tools and gives two buttons: one opens the Full Disk Access
list in System Settings, the other shows `merud` in Finder, ready to drag into
that list.

## Dependency updates

- `google.golang.org/protobuf` moves from an indirect to a direct dependency, at
  the same v1.36.12. Meru uses its `protowire` reader to decode a note's text.
