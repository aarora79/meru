# Release v0.4.9 - Past Chats You Can Find, File, Tag and Delete

**September 2026**

Meru can now read your past chats to answer questions about them, and the chat
list lets you delete chats, sort them into folders, tag them and start chats
that leave nothing behind. Answers also tell the time correctly, and Meru flags
an answer that claims a tool call it never made.

---

## Upgrading from v0.4.8

### Breaking changes

There are no breaking changes to config: no config keys were added, changed or
removed. Three changes need care when you upgrade:

**1. Update `merud`, `meru` and Meru.app together.** The chat list's new
requests (delete, folders, tags, incognito) exist only in v0.4.9's `merud`. An
older `merud` answers them with an error. Both installers update all three at
once.

**2. `meru.db` upgrades itself on the first start.** `merud` adds a `tags`
column to the sessions table (schema step 8). To go back to v0.4.8 afterwards,
restore a copy of `meru.db` from before the upgrade, or delete `meru.db` and let
`merud` rebuild it from your chats and folders.

**3. Two kinds of audit rows no longer come from files.** The `tool_calls`
table normally rebuilds from the chat files. An incognito chat has no file, and
a deleted chat's file is gone, so their tool-call rows, which keep the tool,
time and outcome but no arguments or results, don't survive a rebuild of
`meru.db`. AGENTS.md and ARCHITECTURE.md state this rule.

### Upgrade instructions

**The one-line installer.** Run it again; it keeps your `config.toml`:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and open "Install Meru.app". The first time, macOS refuses because
Apple hasn't checked Meru: click Done, then Open Anyway in System Settings,
Privacy & Security. The installer leaves your config and memories alone.

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.4.9
go install ./cmd/merud ./cmd/meru
make desktop-app && ditto bin/Meru.app /Applications/Meru.app
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # or: pkill merud; merud &
```

## Major features

### Meru reads your past chats

Asked "what were my previous conversations about?", Meru used to say it had no
access to them and list three. The file tools, `list_folder`, `grep` and
`read_file`, now also read `~/.meru/sessions`, where each chat is one JSONL
file, and a line in the prompt says so.

- **Nothing new is indexed.** The chats stay out of the search index, and
  `.jsonl` files are readable only inside the sessions folder. The rest of
  `~/.meru`, such as `config.toml` and `secrets.toml`, stays out of reach.
- **Questions about past chats get the file tools**: one that names a
  previous, earlier or past chat or conversation, or a tag or folder.
- **Long chat lines stay readable**: a `grep` hit shows the 200 characters
  around the match.

### Delete, folders, tags and incognito chats

Right-click a chat in Meru.app, or press Shift+F10, for:

- **Delete:** after a confirmation, `merud` removes the chat's file and its
  content from `meru.db`, so it leaves the list, search and recall. `meru log`
  keeps its tool calls, without arguments or results.
- **Move to folder** and **Remove from folder**. Folders show as groups above
  Today; rename or delete one from its heading. Deleting a folder moves its
  chats back to the list and never deletes them.
- **Tags:** short lowercase words on a chat, up to 12 per chat. They show on
  the chat's row, and search, recall and questions such as "find my chats
  tagged garden" all find them.

**Incognito chat**, a button under New chat, keeps nothing about what you ask:
no chat file, no rows in `meru.db`, no summary, and no memories, since the
`remember` tool is off. Tool calls still pass through the same checks and get
an audit row with the tool, time and outcome, but no arguments or results.
Leaving the chat discards it.

A chat's folder and tags live in a `meta` line of its own JSONL file, and the
folder list in `~/.meru/sessions/folders.json`. `meru chat` has the same
features: `/delete`, `/folder`, `/move`, `/tag`, `/untag`, `/incognito` and
`meru chat --incognito`.

[PR #69](https://github.com/aarora79/meru/pull/69)

### Honest answers about time and tools

Asked for the time, the model once gave a made-up hour and then claimed it had
called the `datetime` tool, which it hadn't.

- **The prompt carries the time** to the minute with the time zone, at its end,
  where it costs about 18 tokens and no reuse of the rest.
- **The honesty rule covers tool calls:** never claim a tool or command ran
  without calling it, and never make up what a tool would return.
- **A check reads each answer** for claimed tool calls and compares them with
  the calls made. When a claim has no call behind it, Meru adds a note: "Meru
  didn't run datetime for this answer, though the answer says it did."
- **The label above an answer shows what happened**: "Used tools" only when a
  tool ran, "Searched your files" when it searched, and "Answered from the
  model" when neither.

## Bug fixes

- Meru.app said "merud isn't running" while `merud` answered questions: its
  status check allows five seconds, and a slow answer on a Mac short of memory
  missed them. A late answer now shows "merud is busy" without telling you to
  start it (#72).
- The label above an answer showed the route the router picked, so it said
  "Used tools" when no tool ran (#71).
