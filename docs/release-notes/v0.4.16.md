# Release v0.4.16 - A Scope Keeps Its Promise

**October 2026**

When you pick where Meru looks, such as "My files" in the desktop app, the
model can now use only the tools that scope offers, even when it names another
from memory. The architecture documents match the code again, and a new page
follows one question through Meru's agent harness.

---

## Upgrading from v0.4.15

### Breaking changes

There are no breaking changes in this release. One behaviour changes on scoped
turns: a model on "My files", "Mail and calendar" or "Web" that names a tool the
scope doesn't offer, such as `web_search` on "My files", gets a refusal instead
of a result. Auto works as before. Pick Auto when a question needs more than one
kind of source.

### New config keys

None.

### Upgrade instructions

**The one-line installer.** Run it again; it keeps your `config.toml`:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and open "Install Meru.app". The first time, macOS refuses because
Apple hasn't checked Meru: click Done, then Open Anyway in System Settings,
Privacy & Security. The installer leaves your config and memories alone.

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.4.16
go install ./cmd/merud ./cmd/meru
make desktop-app && ditto bin/Meru.app /Applications/Meru.app
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # or: pkill merud; merud &
```

## Major features

### A scope fences the tools that run

A scope you pick in the desktop app or `meru chat` promises what the turn may
touch. Until now it limited only what the model saw. A model could still name
a tool from memory, and `dispatch` ran it whenever your config allowed it: on
"My files", a remembered `web_search` searched the web.

- On a scoped turn, Meru hands `dispatch` the tools that round offered, and
  `dispatch` refuses any other. The model reads that the tool isn't offered for
  this question and answers with the tools it has.
- A refused call stays on record: its transcript lines and its `tool_calls`
  row, with the outcome `denied`, so `meru log` shows it.
- Auto turns are unchanged. A route offers fewer tools to keep the prompt
  short, and a model that rightly reaches for another allowed tool shouldn't
  fail for it.
- Meru's own web-first calls on the Web scope run as before.

[PR #136](https://github.com/aarora79/meru/pull/136)

### The architecture documents match the code

A check of ARCHITECTURE.md against the code, line by line, turned up about 70
stale statements, and this release fixes each one. The largest:

- **The scheduler** is marked as planned for v0.5. `config.toml` has no
  `[[jobs]]` key yet.
- **Privacy:** the documents said the answer model never sees an indexed
  picture. `view_image` shows it one, and the documents now say when.
- **Approvals:** three kinds of call ask every time: `configure`, `web_fetch` on
  a URL no search or question gave, and MCP tools in `always_confirm`.

The same fixes reach the level 100 and 200 pages, and seven figures are redrawn.

[docs/architecture/harness.md](https://github.com/aarora79/meru/blob/v0.4.16/docs/architecture/harness.md)
is new. It follows one question through the agent harness, with the numbers the
code uses and seven diagrams.

[PR #129](https://github.com/aarora79/meru/pull/129)

## What's new

- The tools note no longer carries a separate line for local commands. That
  line never reached a prompt with the default config, and turning it on
  changed no answer on the benchmark's command questions: 6 of 9 passed with it
  and without it (#136).
