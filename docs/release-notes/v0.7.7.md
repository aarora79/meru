# Release v0.7.7 - Weekly, monthly and total installs from the daily count, still with no ID

**November 2026**

The anonymous daily count gains six fields, so the project can count how many installs run Meru each week and month, how many are new, how many there are in all, and how many keep coming back. It still holds no ID and no time of day, and Meru asks you again before it sends the new version.

---

## What leaves your machine

The daily report is now version 2, about 250 bytes:

```json
{"v":2,"meru":"0.7.7","os":"darwin","arch":"arm64","profile":"lite","age":"month","questions":"1-5",
 "active_days":"3-5","streak":"2-4","previous":"0.7.6","week_first":true,"month_first":false,"first":false}
```

The first seven fields are the ones v0.7.6 sent. The six new ones:

- **`active_days`**: on how many of the last seven days you asked any question: `0`, `1-2`, `3-5` or `6-7`.
- **`streak`**: how many weeks in a row this install has reported: `1`, `2-4`, `5-12` or `13+`.
- **`previous`**: the Meru version it reported last, such as `0.7.6`, or `none`.
- **`week_first`**, **`month_first`**, **`first`**: true on its first report of the week, of the month, and ever.

Meru works out each one on your computer, from its own record of what it sent and its count of your questions. The three flags are how the project counts installs across days without an ID: each install sets each one once in its window, so counting the reports with a flag counts each install once. [The FAQ](https://github.com/aarora79/meru/blob/v0.7.7/docs/faq/usage-report.md) explains every field and shows how each count works.

- **Meru asks again.** The report's version went up, so `meru chat` and Meru.app show the notice once more, and nothing goes under version 2 until one of them has. If you turned the report off, it stays off.
- **The public totals** at <https://meru-report.meru-workers.workers.dev/> now show active and new installs per day, week and month, the total, and this week's counts by version, system, chip, model set, streak and days used, each on its own.
- **Turn it off** as before: the Usage screen, `/report` in `meru chat`, `meru report off`, `send = "off"` under `[usage_report]`, or `DO_NOT_TRACK=1` in `merud`'s environment.

Meru still sends no crash reports, never checks for updates, and keeps its own measurements on your computer.

## Upgrading from v0.7.6

### Breaking changes

There are no breaking changes in this release. Config, transcripts and `meru.db` don't change, and the socket protocol is the same. The collector keeps taking v0.7.6's version 1 reports.

### New config keys

None.

### Upgrade instructions

**The one-line installer on a Mac.** Run it again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and run "Install Meru.app". It leaves your config and memories alone, and keeps the choice your config already holds.

**Linux.** Run `install-linux.sh` again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install-linux.sh | bash
```

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.7.7
go install ./cmd/merud ./cmd/meru
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # Linux: systemctl --user restart merud
```

Then, on a Mac that reads Apple Notes: macOS drops the Full Disk Access grant
when the `merud` binary changes. In System Settings, open Privacy & Security,
Full Disk Access, and turn `merud` off and on again.

Update Meru.app along with `merud`, so its notice names the new fields.

## Major features

### Report version 2: counts across days with no ID

- Six new fields, each a bucket, a version or true or false, worked out on your computer.
- The collector counts active installs per week and month, new installs and the total from the three flags, the way Fedora counts its systems.
- The notice in every client names the same fields, from one shared text.
- The FAQ explains every field and gives each count with the SQL behind it.
