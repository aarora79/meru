# Release v0.6.2 - The desktop app on Wails beta.34

**October 2026**

A small release: Meru.app and the Mac installer now build on Wails
v3.0.0-beta.34, up from beta.28. Nothing changes in how Meru answers.

---

## Upgrading from v0.6.1

### Breaking changes

This release has no breaking changes. Config keys, `meru.db`, the transcripts
and the socket protocol are unchanged.

### Upgrade instructions

**The one-line installer on a Mac.** Run it again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and run "Install Meru.app". It leaves your config and memories alone.

**Linux.** Run `install-linux.sh` again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install-linux.sh | bash
```

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.6.2
go install ./cmd/merud ./cmd/meru
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # Linux: systemctl --user restart merud
```

If you use the Apple Notes tools, macOS drops the Full Disk Access grant when
the `merud` binary changes. In System Settings, open Privacy & Security, Full
Disk Access, and turn `merud` off and on again.

## What's new

### Dependency updates

  installer's, moves from v3.0.0-beta.28 to v3.0.0-beta.34. CI built and
  checked the desktop app on macOS and on Linux with it. (#156)
