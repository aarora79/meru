# Release v0.5.0 - Scheduled jobs

**October 2026**

Meru now acts on a schedule. It asks a question, runs a skill or runs one of
your declared commands at the times you set, such as every weekday at 7 or
every other Tuesday. Each run lands as a chat in a Jobs folder. You set up jobs
in Settings, in `meru chat`, or by asking for one in chat. Web answers also list
the pages they came from, as links.

---

## Upgrading from v0.4.20

### Breaking changes

There are no breaking changes in this release.

- `merud` adds one column to `meru.db` on its first start, the scheduled job
  each turn ran for. It does this by itself, and `meru.db` can still be rebuilt
  from the transcripts.
- Update Meru.app and `meru` along with `merud`. An older Meru.app works with
  the new `merud`, but it has no Jobs section and shows web sources as plain
  addresses. The new Meru.app with an older `merud` can't list jobs.

### New config keys

| Key | Default | What it does |
|-----|---------|--------------|
| `[[jobs]]` | none | One table per scheduled job: `name`, `schedule` (five-field cron in this computer's time zone), and a `prompt` (with an optional `skill`) or a `command` with its `args`. Optional: `every_weeks` with `from`, for "every other Tuesday"; `allow`, tools a run may use without asking; `output`, a file under the output folder for each answer; `enabled = false` to pause. At most 50. |
| `[builtin] tools` gains `schedule_job` | on | The built-in tool that adds a job when you ask for one in chat. It always asks first. |

A `config.toml` with no `[[jobs]]` runs no jobs. **If your `config.toml`
lists `[builtin] tools` by hand, add `"schedule_job"` to that list**, or asking
Meru for a job won't work; the model will say it can't make one. A config that
leaves the list out gets the tool on by default.

### Upgrade instructions

**The one-line installer.** Run it again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and run "Install Meru.app". It leaves your config and memories alone.

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.5.0
go install ./cmd/merud ./cmd/meru
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # or: pkill merud; merud &
```

If you use the Apple Notes tools, macOS drops the Full Disk Access grant when
the `merud` binary changes. In System Settings, open Privacy & Security, Full
Disk Access, and turn `merud` off and on again.

## Major features

### Scheduled jobs

`merud` runs jobs on a schedule, with the models it already keeps warm.

- **What a job does:** asks a prompt through the usual agent loop, loads a
  named skill for it, or runs one `[[commands]]` entry with no model.
- **When:** five-field cron in this computer's time zone, such as
  `0 7 * * 1-5` for 7:00 on weekdays. `every_weeks` and `from` cover "every
  other Tuesday", which cron can't say. Meru shows each schedule in words, such
  as "9:00 on Tuesdays, every other week from 27 October 2026".
- **After sleep:** a run the Mac slept through runs once on waking, and says it
  ran late, if it's no more than 12 hours late. Older runs are skipped, so
  yesterday's brief doesn't arrive at night. A paused job doesn't catch up when
  you resume it.
- **Where runs go:** each run is a chat in the Jobs folder, first in the chat
  list, named after the job and the time. `output` also writes the answer to a
  file under `~/meru-output`, through the tool log.
- **Approvals:** nobody watches a run, so a tool call that would ask you is
  declined, unless the job's `allow` list names the tool. Changing settings,
  reading a web address nobody gave Meru, and downloads stay declined in a job
  whatever `allow` says.
- **One at a time:** runs share the warm answer model, so they never overlap.
  Each run records the `meru.scheduler.job_runs` and `meru.scheduler.lateness`
  metrics and a `meru.job` trace span.

### Managing jobs in both clients

- **Meru.app:** Settings has a Jobs section. Add a job in a form that shows the
  schedule in words and the next run as you type. Each job has Run now or Stop,
  Pause or Resume, Edit, Remove, and a link to its last run.
- **`meru chat`:** `/jobs` opens the same list. Enter runs a job now, `c` stops
  its run, `p` pauses or resumes, `e` edits, `a` adds, `d` twice removes, and
  `o` opens the last run.
- **Saving:** every change goes through `merud`, which writes `config.toml`,
  keeps your comments, and takes the change at once with no restart.
- **The Jobs folder** can't be renamed or removed while a job exists, since the
  next run would bring it back.

[PR #172](https://github.com/aarora79/meru/pull/172)

### Asking Meru for a job

Say "every weekday at 7, brief me on my calendar", or "create a job to check my
calendar at 8am", and the new built-in tool `schedule_job` proposes the job.

- **The approval card** shows the schedule in words and the next run beside the
  cron fields, so you can see what the model understood. Nothing is saved until
  you approve.
- **Limits:** the tool always asks, and it never sets a job's `allow` list. A
  job's own runs never see `schedule_job` or `configure`, so no job can make or
  change jobs.
- **Routing:** questions that say "schedule", "daily", "every weekday", or
  "job" with a time such as "8am" now reach the tool, even when the router
  first guessed a plain answer.

[PR #173](https://github.com/aarora79/meru/pull/173),
[PR #177](https://github.com/aarora79/meru/pull/177)

### Web pages as an answer's sources

An answer from the web now lists the pages it cites.

- **Numbering:** `web_search` results and pages read with `web_fetch` take the
  numbers after any file excerpts, so `[5]` in an answer names one thing.
- **In the clients:** Meru.app shows each page as a chip with a globe and the
  site's name that opens the page. `meru` and `meru chat` print its title and
  URL as a link.
- **No file search first:** a question Meru treats as a web question, because
  the web-research skill was picked, no longer searches your files first. That
  keeps unrelated files out of the prompt and out of the sources list.

[PR #175](https://github.com/aarora79/meru/pull/175)

## Bug fixes

- A web answer no longer lists unrelated local files as its sources. Its web
  citations used to match the numbers of file excerpts that had nothing to do
  with the question (#175).
- A follow-up answer no longer ends with a run-on block of
  `[from the web: …]` lines. Meru's notes on earlier pages now sit under a line
  that tells the model not to repeat them (#176).
- Editing a job's schedule no longer runs a slot of the new schedule that fell
  before the edit (#172).
