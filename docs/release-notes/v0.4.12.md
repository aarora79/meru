# Release v0.4.12 - Usage Charts in the App, and Prometheus Without Grafana

**October 2026**

The desktop app has a Usage screen of its own, with charts of tasks, tokens and
time to first token over 30 days, drawn from your own `meru.db` with nothing else
to install. `merud` can serve its metrics to a Prometheus you run, and the Grafana
stack in `deploy/` is gone.

---

## Upgrading from v0.4.11

### Breaking changes

There are no breaking changes to `config.toml` or to your chats. Three things
need care:

**1. Update `merud`, `meru` and Meru.app together.** The charts come from a new
kind of `usage` request that only v0.4.12's `merud` answers. A new client
talking to an older `merud` shows the usage table and a line saying the charts
need a newer `merud`. Both installers update all three at once.

**2. The Grafana stack is gone.** `deploy/observability/` no longer exists, so
`docker compose down` can't find it. If you ran it, remove the container and its
data by name, then set `otlp_endpoint = ""` in `~/.meru/config.toml`, or point
it at a collector you run, and restart `merud`:

```sh
docker rm -f meru-lgtm
docker volume rm meru-observability_lgtm-data
```

Until you do, `merud` logs the failed push once an hour.

**3. "questions" is now "tasks".** `meru usage`, `/usage` and the header in
`meru chat` say "tasks": `1h: 4 tasks · 18k in · 2.1k out`. A script that reads
the `questions` row of `meru usage` needs the new label.

### New config keys

| Key | Default | What it does |
|-----|---------|--------------|
| `[observability] prometheus` | `""` | A loopback `host:port`, such as `"127.0.0.1:9464"`, where `merud` serves its metrics at `/metrics` for a Prometheus you run. Empty serves nothing. `merud` refuses any other address. |

A `config.toml` from v0.4.11 loads as it is, with `/metrics` off.

### Upgrade instructions

**The one-line installer.** Run it again; it keeps your `config.toml`:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and open "Install Meru.app". The first time, macOS refuses because
Apple hasn't checked Meru: click Done, then Open Anyway in System Settings,
Privacy & Security. The installer leaves your config and memories alone.

**From source.** The build now needs Go 1.26.9; with the default
`GOTOOLCHAIN=auto`, `go` downloads it for you.

```sh
cd meru
git pull origin main
git checkout v0.4.12
go install ./cmd/merud ./cmd/meru
make desktop-app && ditto bin/Meru.app /Applications/Meru.app
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # or: pkill merud; merud &
```

## Major features

### The Usage screen

Usage has its own button beside Settings at the foot of the rail, and two tabs.

- **Charts**, open first: the usage table, then four bar charts over 30 days,
  two to a row: tasks per day, time to first token per day (p50 over p95), tokens
  in and tokens out. Each chart has a labelled y axis with round ticks, dates along
  the bottom, and the day's value when you hover a bar. A task is one question or
  request that Meru answered.
- Under the charts: the ten slowest tasks of the week, each a link to its chat;
  tool calls over 30 days by outcome, with failures in red; and use by answer
  model.
- **Prometheus queries**: the `/metrics` address, or the line that turns it on,
  and six PromQL queries with Copy buttons.
- Everything comes from `meru.db`, which `merud` rebuilds from your transcripts,
  so the screen needs no other program.

`/usage` in `meru chat` shows the same numbers as text: bar lines of tasks and
tokens in for the last 14 days, today's tokens and time to first token, the five
slowest tasks, and the tools whose calls failed.

[PR #107](https://github.com/aarora79/meru/pull/107)

### `/metrics` for Prometheus

With `[observability] prometheus = "127.0.0.1:9464"`, `merud` serves every
metric it records at `http://127.0.0.1:9464/metrics`, in Prometheus's text
format.

- **No new dependency.** A second reader beside the OTLP push collects the
  metrics on each request, and `merud` writes the text itself.
- **Same names as before.** Names follow the OpenTelemetry Collector's rules,
  such as `meru_turn_duration_seconds` and `meru_tool_calls_total`, so queries
  written for the old Grafana stack keep working.
- **This machine only.** The address must be loopback. The page answers GET and
  HEAD on `/metrics` alone, and refuses a request whose `Host` names anything but
  this machine, so a web page in your browser can't read it.
- Counters start from zero when `merud` restarts; `increase()` and `rate()`
  allow for that.

The OTLP push stays for anyone who runs a collector, and still carries traces.
[docs/observability.md](https://github.com/aarora79/meru/blob/v0.4.12/docs/observability.md)
has the scrape job and the queries.

[PR #107](https://github.com/aarora79/meru/pull/107)

## Security fixes

- Go 1.26.9 in place of 1.26.6, which fixes twelve advisories in `crypto/tls`,
  `html/template`, `net/http`, `net/textproto` and `os` (#108).
- `golang.org/x/net` v0.60.0, which fixes five advisories (#98, #108).
