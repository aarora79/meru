# Release v0.4.19 - Room to Read

**October 2026**

A question that reads many web pages now finishes. Meru gives the answer
model a context window sized for it and your Mac, `qwen3.6:35b` gets its full
262,144 tokens on a 64 GB Mac, and a turn keeps its prompt inside that window.
When an answer still stops short, Continue picks it up, and you can let Meru
read a website without asking each time.

---

## Upgrading from v0.4.18

### Breaking changes

There are no breaking changes in this release.

Three things to know:

- **The answer model may use more memory.** `merud` now gives it as much
  context window as its cache fits in an eighth of your Mac's memory, and
  Ollama sets that memory aside when the model loads. `qwen3.6:35b` on a
  64 GB Mac went from 23.4 GB to 28.8 GB. `merud.log` names the window at
  startup: `answer model window model=qwen3.6:35b window=262144`.
  `[ollama] context_length` is now the least the answer model gets.
- **Apple Notes needs its grant again.** A new `merud` build loses its Full
  Disk Access. After the update, open System Settings, Privacy & Security,
  Full Disk Access, and turn `merud` off and on again.
- **Update Meru.app with `merud`.** The Continue button and the website
  buttons need both.

### New config keys

| Key | Default | What it does |
|-----|---------|--------------|
| `[web] trusted_sites` | `[]` | websites `web_fetch` reads without asking, in every chat; "Always allow" at the prompt adds one |

A `config.toml` without the key trusts no website, as before.

### Upgrade instructions

**The one-line installer.** Run it again; it keeps your `config.toml`:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and open "Install Meru.app". The first time, macOS refuses because
Apple hasn't checked Meru: click Done, then Open Anyway in System Settings,
Privacy & Security. The installer leaves your config and memories alone.

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.4.19
go install ./cmd/merud ./cmd/meru
make desktop-app && ditto bin/Meru.app /Applications/Meru.app
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # or: pkill merud; merud &
```

Then give `merud` Full Disk Access again if you use Apple Notes.

## Major features

### A context window sized for the answer model

Before, every model got 32,768 tokens. With the full model set, the first
prompt took 24,485 of them before any search: the system prompt, skills,
excerpts and about 15,000 tokens of tool descriptions. A news question had
room for four or five pages.

- **Per model.** At startup and on each model switch, `merud` asks Ollama
  how many tokens the answer model can read and how its attention layers are
  shaped, and works out the memory one token of cache takes.
- **Capped by memory.** The window is the model's most, cut to what fits in
  an eighth of the Mac's memory, and never less than `[ollama]
  context_length`. `qwen3.6:35b` caches in one layer of four, about 20 KB a
  token, so its 262,144 tokens cost 5 GB. A dense model of its size takes up
  to ten times as much a token and gets less.
- **The rest stay as they were.** The fast and embedding models, and any
  model Ollama can't describe, such as `gemma4`, keep `context_length`.

[PR #160](https://github.com/aarora79/meru/pull/160)

### A turn's tool rounds stay inside the window

Each tool round sends every earlier result again. A turn that read about
twenty pages added up to 169,000 prompt tokens, and Ollama cut its answer off
after 650 words.

- **Old results shrink first.** Past 80% of the window, Meru cuts the turn's
  oldest tool results to 400 characters, with a note that the model can call
  the tool again. The newest results and the transcript stay whole.
- **Tools stop, and the answer comes.** When that isn't enough, later rounds
  offer no tools, and a model that tries one anyway gets one more round told
  to answer from what it has, instead of showing you its plan as the answer.
- **It says so.** Such a turn ends with a new outcome, `window_full`, and a
  note under the answer that names the window and points at Continue.

[PR #157](https://github.com/aarora79/meru/pull/157)

### Continue an answer that stopped short

An answer that stopped at the length limit, ran out of time, or filled the
window gets a Continue button in Meru.app, and a line pointing at
`/continue` in `meru chat`. `merud` reads the last turn from the transcript
and hands the model your question and each tool call it made, with the
start of each result, so it picks up where it stopped without reading the
same pages again. The `done` event now carries the outcome, so scripts on
`meru run --json` can tell a whole answer from part of one.

[PR #158](https://github.com/aarora79/meru/pull/158)

### Trust a website, for a chat or always

When `web_fetch` asks before reading a page no search or question gave, the
prompt now names the website and offers "Allow it for this chat" and "Always
allow". Always adds the site to `[web] trusted_sites`. Settings lists the
sites with a Remove button, and `meru chat` has `/sites` and `/sites remove
<site>`. Each choice covers that exact host, with no wildcard, and downloads
still ask every time.

[PR #155](https://github.com/aarora79/meru/pull/155)

## What's new

### Reading the web
- `web_fetch` reads pages up to 16 MiB, up from 5 MiB. CNN's world page is
  5.5 MB, almost all scripts, and Meru refused it whole; its headlines come
  to 17,000 characters, read in 23 ms (#159).

### The clients and the site
- Both clients link to Meru's website, Meru.app from a globe at the top
  right and `meru chat` from its header (#153).
- The landing page shows the latest release and how long ago it came out,
  and where the name Meru comes from (#151).
- Two slide decks, one for anyone and one for developers, in HTML and PDF,
  linked from the README and the landing page (#152, #153).

### Under the hood
- The turn span records `meru.turn.shortened_results` and
  `meru.turn.window_full`, and `meru.turn.duration` counts `window_full`
  turns (#157).
- The toolchain moved to Go 1.26.10 for GO-2026-6809 in `crypto/x509`
  (#157, #159).
