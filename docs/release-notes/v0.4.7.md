# Release v0.4.7 - Benchmark Charts of Accuracy Against Time

**September 2026**

The benchmark results now open with the answer model each size of Mac gets, and
two charts show every model's pass rate against how long it takes to answer.
Installs pick the same models as v0.4.6, and new tests keep every installer on
one model table.

---

## Upgrading from v0.4.6

### Breaking changes

There are no breaking changes in this release. No config keys were added,
changed or removed, the default models are the same, and `merud`, `meru` and
Meru.app speak the same protocol as in v0.4.6.

### Upgrade instructions

**The one-line installer.** Run it again; it keeps your `config.toml`:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and run "Install Meru.app". It leaves your config and memories alone.

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.4.7
go install ./cmd/merud ./cmd/meru
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # or: pkill merud; merud &
```

## Major features

### Accuracy against time in the benchmark results

[docs/benchmarks/results.md](../benchmarks/results.md) ranked the model sets by
pass rate and by time in separate bar charts. Two new charts put both on one
picture, so you can see which models are fast and accurate at once.

- One chart plots pass rate against the median time to the first token, the
  other against the median time to the last. The best models sit top left.
- Each model keeps one colour in both charts, and a key under each chart gives
  its figures.
- Where two models sit close together, as the two Qwen builds do, one name
  prints above its dot and the other below, so both stay readable.

[PR #63](https://github.com/aarora79/meru/pull/63)

### The default model for each Mac, at the top of the results

The results page now opens with the answer model the installers pick for each
amount of memory, with that model's pass rate and median times:

| Mac memory | Default answer model | Passed | Time to first token | Time to last token |
|------------|----------------------|-------:|--------------------:|-------------------:|
| under 32 GB | MiniCPM5-2B, the `lite` model | 68% | 11.6 s | 13.1 s |
| 32 to 47 GB | `gemma4:26b-a4b-it-qat` | 80% | 17.6 s | 18.3 s |
| 48 to 63 GB | `qwen3.6:35b` | 89% | 5.6 s | 10.4 s |
| 64 GB or more | `qwen3.6:35b-a3b-mxfp8` | 89% | 4.1 s | 6.5 s |

`meru check report` builds the table from the Mac installer's own model table,
so the page shows what the installers do.

[PR #63](https://github.com/aarora79/meru/pull/63)

## What's new

### Installers
- Two tests fail the build when `scripts/install.sh` or the `meru-install`
  skill names a different model for a Mac's memory from the Mac installer's
  table, so a change of default can't leave one installer behind (#63).

### Documentation
- The benchmark results page is regenerated with the new table and charts
  (#63).
