# Release v0.7.5 - One anonymous count a day, and a model that retries a call it got wrong

**November 2026**

Meru can now send one anonymous count a day, so the project can tell how many installs run it and on what. It is off for everyone who upgrades until they say yes. This release also has the model call a tool again when it left out an argument, and it says so when a failed call left an answer short.

---

## What leaves your machine

Until this release, Meru promised that nothing about it left your computer. That changes in one way, and this section says exactly how.

Once a day, Meru can send one small report, about 100 bytes:

```json
{"v":1,"meru":"0.7.5","os":"darwin","arch":"arm64","profile":"lite","age":"month","questions":"1-5"}
```

That's the Meru version, your system and chip, the model set, a rough install age (a week, a month, a year or older) and a rough count of yesterday's questions (0, 1 to 5, 6 to 20, or more). It holds no ID, no question or answer, no file name and no setting. Meru is free and has no accounts, so this count is the project's only way to know how many people run it, on which systems, and which releases they keep.

- **If you're upgrading, nothing changes until you say yes.** Your config has no choice in it yet, so Meru sends nothing. `meru chat` and Meru.app ask you once, with **Share** and **Don't share**.
- **A new install asks during setup,** with the answer on. Even then Meru sends nothing until `meru chat` or the app has shown you the notice, and the first report waits until the next day.
- **Where it goes:** a small program the project runs on Cloudflare, at `https://meru-report.meru-workers.workers.dev`. It stores the date and the seven fields, with no IP address, keeps them 400 days, and keeps no logs. Cloudflare's network sees your IP address when the report arrives, as any website does; the project never stores it. The totals from every install are public at <https://meru-report.meru-workers.workers.dev/>.
- **You can see every report.** `~/.meru/usage-report.jsonl` holds each one exactly as sent. The Usage screen, `/usage` in `meru chat` and `meru report` show them, with the next one and when it goes.
- **Turn it off** with the switch on the Usage screen, `/report` in `meru chat`, `meru report off`, or `send = "off"` under `[usage_report]` in `config.toml`. `DO_NOT_TRACK=1` in `merud`'s environment stops it too.
- **Send today's now.** The Usage screen's button, `t` in `/report` and `meru report send` send today's report at once. They never send a second one the same day.

Meru still sends no crash reports and never checks for updates, and its own measurements stay on your computer. [The FAQ](https://github.com/aarora79/meru/blob/v0.7.5/docs/faq/usage-report.md) has the details, and [ARCHITECTURE.md, "Anonymous usage report"](https://github.com/aarora79/meru/blob/v0.7.5/ARCHITECTURE.md#anonymous-usage-report), is the full rule.

## Upgrading from v0.7.4

### Breaking changes

There are no breaking changes in this release. Every config key from v0.7.4 still loads, and the transcripts and `meru.db` don't change. The socket protocol gains one op, `usage_report`, and one event. An older `meru chat` or Meru.app never asks for it, so it shows no notice, and with no notice shown `merud` never sends.

### New config keys

| Key | Default | What it does |
|-----|---------|--------------|
| `[usage_report] send` | `""` | `"on"` sends the anonymous daily count, `"off"` never sends it, and `""` means you haven't chosen: Meru asks in `meru chat` and the app, and sends nothing until you say yes. |
| `[usage_report] url` | `""` | Another collector to send the count to; empty means Meru's own. An address off this machine must use https. |

A `config.toml` without the table reads as not chosen.

### Upgrade instructions

**The one-line installer on a Mac.** Run it again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and run "Install Meru.app". It leaves your config and memories alone, and its last step keeps the choice your config already holds.

**Linux.** Run `install-linux.sh` again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install-linux.sh | bash
```

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.7.5
go install ./cmd/merud ./cmd/meru
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # Linux: systemctl --user restart merud
```

Then, on a Mac that reads Apple Notes: macOS drops the Full Disk Access grant
when the `merud` binary changes. In System Settings, open Privacy & Security,
Full Disk Access, and turn `merud` off and on again.

Update Meru.app along with `merud`: the notice, the Usage section and Send today's now come with the new app. A build from source calls itself a development build, which never sends a report.

## Major features

### The anonymous daily usage report

- One report a UTC day at most, at a random minute in the two hours after midnight UTC, or soon after the computer wakes.
- Sent only when you chose "on", `DO_NOT_TRACK` is unset, the build is a release, and a client showed you the notice on an earlier day.
- A notice in both clients until you act on it, an "Anonymous daily count" section on both Usage screens, `/report` in `meru chat`, and `meru report [on|off|send]`.
- A new step in `meru setup` and a ticked box on the Mac installer's last step for a new install; an update keeps the choice you made.
- The model can't change the setting: no built-in tool may touch `[usage_report]`, and a test checks it.
- The collector's code is in [`collector/`](https://github.com/aarora79/meru/tree/v0.7.5/collector): a Worker that stores a report only when it holds exactly the seven fields and their allowed values.

[PR #252](https://github.com/aarora79/meru/pull/252)

### A second try for a call that left out an argument

When a tool refuses a call because an argument is missing, `dispatch` tells the model which one and to call again, and suggests another tool that may give the value first, such as one that lists your accounts. After an answer, a call that failed with no later call to the same tool that worked gets a notice: the tool failed, so the answer goes without what it would have read.

[PR #250](https://github.com/aarora79/meru/pull/250)
