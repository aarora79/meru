# Release v0.8.1 - Meru reads your files when you attach a picture, and thanks gets a quick reply

**November 2026**

Two fixes from real chats. A question with a screenshot attached can now read your files, PDFs included, and a short "thanks" or "great job" gets a reply in about a second instead of a minute.

---

## Upgrading from v0.8.0

### Breaking changes

There are no breaking changes in this release. Config, transcripts and `meru.db` don't change, the socket protocol is the same, and the daily report stays at version 2.

### New config keys

None.

### Upgrade instructions

**The one-line installer on a Mac.** Run it again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and run "Install Meru.app". It leaves your config and memories alone.

**Linux.** Run `install-linux.sh` again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install-linux.sh | bash
```

**Windows.** In PowerShell; run it again later to update:

```powershell
irm https://github.com/aarora79/meru/releases/latest/download/install.ps1 | iex
```

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.8.1
go install ./cmd/merud ./cmd/meru
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # Linux: systemctl --user restart merud
```

Then, on a Mac that reads Apple Notes: macOS drops the Full Disk Access grant
when the `merud` binary changes. In System Settings, open Privacy & Security,
Full Disk Access, and turn `merud` off and on again.

Both fixes live in `merud`, so updating `merud` is enough; Meru.app and `meru` change only in their version number.

## Bug fixes

- A question with a picture attached now offers the file tools. Such a question skips the router, whose model reads text alone, and took the `direct` route, which offered no `read_file`. Asked to read a PDF the chat had already found, with a screenshot attached, the model tried `web_fetch` on a `file://` link and said it couldn't open PDFs. The turn now offers the same tools a file search does, and still searches nothing first (#275)
- A short message of thanks, praise or greeting, such as "great job Meru! Yay!!!" or "thanks, that worked", now goes `direct`, where the fast model replies. The router scored that message below `min_confidence`, so it took the `search+tools` fallback, and the main model read a 39,844-token prompt for 52 seconds before a short thank-you. "yes" and "ok" still go to the router, since they often answer a question Meru asked, and a message with any other word, such as "thanks, now read the other one", routes as before (#276)
- The `desktop-linux` workflow, which adds the Linux desktop app to a release, refused v0.8.0 because the new Windows desktop app's file name starts the same way. It now looks for the Linux archive by name, and v0.8.0 got its Linux desktop app (#273)
