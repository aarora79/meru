# Release v0.4.11 - Pages That Need JavaScript, and Connectors You Set Up in Settings

**October 2026**

`web_fetch` now reads pages that build their text with JavaScript, such as job
postings, through a headless Chrome that Meru runs for one page at a time. Google
joins Obsidian and web search as a connector that Meru installs and runs, and
you can now set up, repair and adopt connectors from Settings, `meru chat`, `meru`
and the Mac installer, with no config editing or restart.

---

## Upgrading from v0.4.10

### Breaking changes

There are no breaking changes to config or to your chats. Two things need care:

**1. Update `merud`, `meru` and Meru.app together.** The new requests that set
up, repair and adopt a connector exist only in v0.4.11's `merud`. Both installers
update all three at once.

**2. Going back to v0.4.10 needs a config edit** if you have added `allow`,
`confirm` or `always_confirm` lists inside a `[connectors.*]` table: v0.4.10's
`merud` refuses to start on a list there. Take them out of `config.toml` first.
Going back to v0.4.9 or earlier means taking out every `[connectors.*]` table.

### New config keys

| Key | Default | What it does |
|-----|---------|--------------|
| `[web] render` | `"auto"` | `"auto"` loads a page that needs JavaScript in a headless Chrome; `"off"` reads every page as plain HTML |
| `[connectors.google] enabled` | `false` | `true` lets `merud` install and run the Google server (`workspace-mcp` 1.30.0) on 127.0.0.1:8000 |
| `[connectors.google] email`, `client_id` | none | Your Google address and your OAuth client's ID; the client secret goes in `secrets.toml` as `connector_google_client_secret` |
| `allow`, `confirm`, `always_confirm` in `[connectors.obsidian]` or `[connectors.google]` | the manifest's lists | Which of the server's tools the model may use, and which ask first |

A `config.toml` from v0.4.10 loads as it is: rendering is on, and Google stays
off until you turn it on.

### Upgrade instructions

**The one-line installer.** Run it again; it keeps your `config.toml`:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and open "Install Meru.app". The first time, macOS refuses because
Apple hasn't checked Meru: click Done, then Open Anyway in System Settings,
Privacy & Security. The installer leaves your config and memories alone.

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.4.11
go install ./cmd/merud ./cmd/meru
make desktop-app && ditto bin/Meru.app /Applications/Meru.app
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # or: pkill merud; merud &
```

**Already run Google or Obsidian yourself?** Nothing changes: your
`[[mcp.servers]]` entry keeps running, and its card in Settings shows a green
"Your setup" pill. Adopt, there or with `meru mcp adopt google`, is optional: it
moves the server under `merud`, which then runs and restarts it. It shows every
change and asks first, and `meru mcp unadopt google` puts the old entry back.

## Major features

### Pages that need JavaScript

Many pages send an empty HTML shell and fill it in with JavaScript: job boards
such as Workday, many docs sites, most single-page apps. `web_fetch` found no text
there, and the model answered from search snippets. On one Workday job page it
got the location and the date wrong. The same page now reads in full, about
10,900 characters, in about 3 seconds.

- **Only when needed.** `web_fetch` reads the HTML first. A page with under 500
  characters of text and a script on it goes to the browser; any other page
  reads as before.
- **A pinned browser, installed on first need.** `merud` downloads
  `chrome-headless-shell` 154.0.8037.92 from Google's Chrome for Testing into
  `~/.meru/runtime`, about 95 MB, and checks it against a pinned SHA-256. While it
  downloads, the tool line in Meru.app, `meru chat` and `meru` says "Installing
  Meru's page reader (about 95 MB, once)". Nothing downloads until a page needs
  it, and Meru never uses your own Chrome.
- **One Chrome per page.** Each page gets a fresh Chrome and a fresh profile,
  driven through two pipes with no network port, and both stop when the page is
  read. No browser runs between pages, and no cookie outlives a call.
- **The same guard as a fetch.** Every request the page makes goes through a
  proxy in `merud` that refuses this machine and your network, after DNS. The
  proxy refuses everything until the page starts to load, so Chrome's own
  background traffic goes nowhere, and QUIC and WebRTC stay off. Tests prove each
  of these against the real browser.
- **Off.** `[web] render = "off"` reads every page as plain HTML. Windows has no
  browser pin yet.

`meru.web.render.duration` times each rendered page, and a new Grafana panel
shows it.

[PR #101](https://github.com/aarora79/meru/pull/101)

### Google as a connector, and Adopt

`merud` can now install and run the Google server for Gmail, Calendar and Drive,
as it runs Obsidian and web search.

- **Install and run.** With `[connectors.google]` on, `merud` installs
  `workspace-mcp` 1.30.0 into `~/.meru/runtime`, starts it on 127.0.0.1:8000,
  checks it with a read-only calendar call, and restarts it after a crash. It
  never stops a program it didn't start that holds the port.
- **Sign-in.** Until you sign in, the card in Settings shows a **Sign in to
  Google** button, and `meru mcp status` and `/mcp` show the link. `merud` checks
  again every 15 seconds and moves to ready once you have signed in. The link
  never lands in `merud.log`.
- **Adopt.** A server you set up by hand, such as the `google` entry an older
  installer wrote, keeps running as it is. Adopt moves it over: it shows the plan,
  asks, then edits `config.toml` and the launchd job, and `meru mcp unadopt` undoes
  it.

[PR #95](https://github.com/aarora79/meru/pull/95)

### Set up and fix connectors from the clients

Turning a connector on used to mean editing `config.toml` and restarting
`merud`. Now:

- **Settings, Connections** opens with a card per connector: Obsidian, Google,
  Web search and Ollama. Each card has its state, an on and off switch, a form
  for its settings (a folder picker for Obsidian's vault, a hidden field for a
  secret), Save, and **Fix**, which marks what is missing. The card shows each
  step as `merud` installs and checks.
- **`/mcp` in `meru chat`** lists the connectors first: `f` runs Fix and asks for
  each missing field, `o` turns one on or off, `a` adopts.
- **`meru mcp set <id> key=value…`** and **`meru mcp fix <id>`**. A secret named
  alone, such as `client_secret`, is read without echo; `meru` refuses one typed
  as `client_secret=…`, which your shell history would keep.
- Secrets go to `secrets.toml` (mode 0600) and never into `config.toml`, a log or
  an event.

[PR #96](https://github.com/aarora79/meru/pull/96)

### The installer and `meru setup` hand connectors to merud

- **The Mac installer** has ten steps, with a new **Obsidian notes** step. The
  web search, Obsidian and Google steps gather what each needs, and **Start Meru**
  hands them to `merud`, showing each step it reports. When Google waits for a
  sign-in, the last screen has a **Sign in to Google** button.
- The installer no longer runs Docker, uv or a launchd job for connectors itself,
  and no longer keeps the Google client secret in a start script. An existing
  SearXNG or hand-set server keeps working: `merud` watches it, and Adopt is
  offered, never forced.
- **`meru setup`** offers the same: web search run by `merud`, and Obsidian and
  Google field by field, or Adopt for one set up by hand.

[PR #97](https://github.com/aarora79/meru/pull/97)

## What's new

### Settings and the rail
- A server you set up by hand reads as working: a green "Your setup" pill, the
  sentence "There is nothing to do.", and Adopt as an optional, secondary button,
  where the card used to look like an error (#102).
- The rail lists the connectors as one line of names that wraps like text, with
  an amber dot only on one that needs attention (#102).
- The chat list in the rail is tighter, and chat folders start closed unless they
  hold the open chat; a search still opens them all (#102).

### For scripts
- A slow tool sends `progress` events between its `tool_call` and `tool_result`,
  with the call's ID; `meru run --json` passes them through (#101).
