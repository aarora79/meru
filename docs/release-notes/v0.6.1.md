# Release v0.6.1 - Clearer installer messages, and the docs caught up

**October 2026**

A small release with no change to how Meru answers. The Linux installer now
says when `merud` starts: at each login, and at boot only if you let it turn
on linger. The docs, slides and poster now say what v0.6.0 does, and the
poster shows every milestone through v0.6.

---

## Upgrading from v0.6.0

### Breaking changes

This release has no breaking changes for people who run Meru. Config keys,
`meru.db`, the transcripts and the socket protocol are unchanged.

**If you build from a clone of the repository:** on 28 October the owner
rewrote the commit messages on `main` after v0.5.0 to remove co-author
trailers, and moved the `v0.6.0` tag to the rewritten commit. The code at
every commit is the same; only the commit IDs changed. Reset your clone:

```sh
git fetch origin --tags --force
git checkout main
git reset --hard origin/main
```

### Upgrade instructions

**The one-line installer on a Mac.** Run it again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and run "Install Meru.app". It leaves your config and memories alone.

**Linux.** Run `install-linux.sh` again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install-linux.sh | bash
```

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.6.1
go install ./cmd/merud ./cmd/meru
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # Linux: systemctl --user restart merud
```

If you use the Apple Notes tools, macOS drops the Full Disk Access grant when
the `merud` binary changes. In System Settings, open Privacy & Security, Full
Disk Access, and turn `merud` off and on again.

## What's new

### Linux installer
- `install-linux.sh` says the `merud` service starts at each login. It asks
  separately before it turns on linger, which starts `merud` at boot. Before,
  its first question said "at every boot". Its other messages are shorter and
  name who does what. (#190)

### Documentation
- The README, the install FAQ and `docs/running.md` say the same about login
  and boot. The README's Voice row says "your computer", since speech to text
  runs on Linux too. (#190)
- A pass over the prose the Linux pull requests added: passive sentences given
  an actor, GPU and WSL spelled out on first use, padding cut, and a few facts
  fixed. A workflow comment had claimed whisper hears a minute of speech in a
  second; the measured figure is a 4-second clip in 1.4 seconds. (#190)
- The overview and organizations slide decks are printed again. (#190)
- The poster names the `full` profile's answer model, `qwen3.6:35b-a3b-mxfp8`,
  the four built-in skills and `schedule_job`, shows all six milestones
  through v0.6 as shipped, and gives the measured 89% pass rate. It had still
  said v0.2. (#191)
