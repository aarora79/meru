# Release v0.8.0 - Meru on Windows

**November 2026**

Meru now runs on Windows: `merud`, `meru`, `meru chat` and the desktop app, with Ollama on an NVIDIA GPU, your files and web search. A new installer, `install.ps1`, sets it all up from one line in PowerShell. Fixes found on Windows also mend links to files on every system.

---

## Upgrading from v0.7.8

### Breaking changes

There are no breaking changes in this release. Config, transcripts and `meru.db` don't change, the socket protocol is the same, and the daily report stays at version 2.

One check is stricter: a scheduled job's `output` that starts with `/` or `\`, or names a drive, now fails config on every system, as an absolute path always did. It must name a place inside `[skills] output_dir`, such as `briefs/{date}.md`.

### New config keys

None.

### Upgrade instructions

**The one-line installer on a Mac.** Run it again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and run "Install Meru.app". It leaves your config and memories alone.

**Linux.** Run `install-linux.sh` again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install-linux.sh | bash
```

**Windows.** In PowerShell; run it again later to update:

```powershell
irm https://github.com/aarora79/meru/releases/latest/download/install.ps1 | iex
```

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.8.0
go install ./cmd/merud ./cmd/meru
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # Linux: systemctl --user restart merud
```

Then, on a Mac that reads Apple Notes: macOS drops the Full Disk Access grant
when the `merud` binary changes. In System Settings, open Privacy & Security,
Full Disk Access, and turn `merud` off and on again.

A Windows clone needs Git to keep the repository's line endings. This release
adds a `.gitattributes` file that does it; for a clone made before it, see
[docs/windows.md](https://github.com/aarora79/meru/blob/v0.8.0/docs/windows.md).

## Major features

### Meru on Windows

Until now Windows builds were only compiled, never run. This release ran Meru on Windows Server 2025 with an NVIDIA L40S and fixed what broke.

- `merud`, `meru`, `meru chat` and the desktop app run on Windows. The desktop app draws through WebView2, which Windows 11 and recent Windows Server ship.
- `meru setup` reads the processor, memory and NVIDIA GPU on Windows, and offers the answer model that fits the GPU's memory, as on Linux.
- `merud` notices when Ollama stops on Windows and waits for it, and sign-ins to MCP servers on the internet, such as GitHub's, stay saved between runs.
- Release builds now include the Windows desktop app, `meru-desktop-v0.8.0-windows-amd64.zip`, checked by `SHA256SUMS` like every other file.

Web search needs Docker or Podman, which on Windows run through WSL2. On a machine that can't run them, such as a cloud GPU server without nested virtualization, [docs/windows.md](https://github.com/aarora79/meru/blob/v0.8.0/docs/windows.md) shows how to run SearXNG on Python instead. Connectors that Meru installs and runs, such as Obsidian and Google, don't run on Windows yet. [Issue #85](https://github.com/aarora79/meru/issues/85) tracks what's left.

[PR #271](https://github.com/aarora79/meru/pull/271)

### The Windows installer

`install.ps1` is `install-linux.sh` for Windows. It lists what it will install and asks once, then:

- checks the release against `SHA256SUMS` and puts `meru` and `merud` in `%LOCALAPPDATA%\Programs\Meru`, on your PATH;
- installs the desktop app with a Start menu entry;
- on Windows Server with an NVIDIA card and no driver, installs NVIDIA's data-center driver, after checking NVIDIA's signature;
- installs Ollama, after checking Ollama's signature;
- runs `meru setup`;
- adds a Task Scheduler task that starts `merud` at each sign-in, with no window.

It downloads only from GitHub, ollama.com and nvidia.com, and sends nothing. `MERU_FROM` installs from a folder of release files instead, such as a build of your own.

[PR #271](https://github.com/aarora79/meru/pull/271)

## Bug fixes

These showed up on Windows; the first two affect every system.

- An answer that linked a file as `file:///~/notes/plan.md` gave a link that opened nothing, and a warning that the file didn't exist when it did. Models write `~` because Meru shows them paths that way. Meru now reads `~` as your home folder when it checks a link, when you click one, and in the pages `write_file` saves (#271)
- `meru chat` with no terminal, as from a script, waited for keys on Windows. It now stops at once on every system and points to `meru "question"` (#271)
- A link with a Windows drive, such as `file://C:/Users/...`, lost its drive, so the missing-file warning named the wrong path and a picture in the output folder counted as outside it (#271)
- `web_fetch`'s list of sites it may fetch without asking could forget the chat you were in: on Windows two uses could share one timestamp (#271)
- Unpacking a connector's download on Windows made links that led nowhere (#271)
- A Windows clone checked every text file out with Windows line endings, which broke `meru setup`'s config template in a build from source. A new `.gitattributes` keeps them as they are (#271)
