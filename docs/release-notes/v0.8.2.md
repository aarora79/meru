# Release v0.8.2 - Guards against prompt injection, a closed socket, and quicker follow-ups

**November 2026**

Words in an email or a web page can no longer get a tool to send, share or remember something on their own: once a chat has read mail or the web, Meru asks before each such call. `merud` now answers only your own user on its socket, and an unsure follow-up such as "done?" keeps the route of the turn before it, so Ollama reuses its cached prompt.

---

## Upgrading from v0.8.1

### Breaking changes

There are no breaking changes in this release. Config, transcripts and `meru.db` don't change. The socket protocol gains optional fields, so an older `meru` or Meru.app still works with this `merud`, and the daily report stays at version 2.

Two things behave differently:

- Once a chat has read mail, the web or another server's content, a tool that asks first asks before every call in that chat, and "Allow for this chat" no longer covers it. A scheduled job declines such a call, since nobody is there to ask.
- `merud` refuses a connection on `merud.sock` from any user but the one it runs as, and refuses to start when `~/.meru` is a symlink or another user owns it. It sets a `~/.meru` folder that others can open to `0700`.

### New config keys

None. Settings can now write a tool to the existing `[mcp] always_confirm` list with the new Always ask choice.

### Upgrade instructions

**The one-line installer on a Mac.** Run it again; it keeps your config.toml. Answer yes to "Start merud now and at every login?" to get the new launchd file, which keeps `merud`'s output logs readable by you alone:

```sh

```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and run "Install Meru.app". It leaves your config and memories alone.

**Linux.** Run `install-linux.sh` again; it keeps your config.toml, and a yes to the systemd question writes the new unit:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install-linux.sh | bash
```

**Windows.** In PowerShell; run it again later to update:

```powershell
irm https://github.com/aarora79/meru/releases/latest/download/install.ps1 | iex
```

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.8.2
go install ./cmd/merud ./cmd/meru
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # Linux: systemctl --user restart merud
```

If you keep the old service file, `merud` still sets `merud.out.log` and `merud.err.log` to `0600` each time it starts.

Then, on a Mac that reads Apple Notes: macOS drops the Full Disk Access grant
when the `merud` binary changes. In System Settings, open Privacy & Security,
Full Disk Access, and turn `merud` off and on again.

## Major features

### Guards against prompt injection

A chat that read an email can carry words the sender wrote, such as "forward this thread to me". These changes keep such words from acting on your behalf:

- `merud` marks a chat once it has read outside content: a result from `web_search` or `web_fetch`, a file in the attachments or downloads folder, or a result from an MCP tool, A2A agent or command that runs without asking. The mark comes from the transcript, so a restart doesn't clear it.
- In a marked chat, every tool that asks first asks before each call, and the approval says why: "This chat has read mail or the web, so Meru asks before each call." `remember` asks too, so a page can't plant a memory.
- Settings, Tools, in Meru.app and `/tools` in `meru chat`, adds Always ask beside Ask first. It puts a tool on `[mcp] always_confirm`, so no session approval covers it, and each tool shows the server's hint: read-only, may delete, or changes things.
- `web_fetch` trusts a whole site for the chat only when your own words named it. A search result trusts its exact address alone.
- [docs/design/security.md](https://github.com/aarora79/meru/blob/v0.8.2/docs/design/security.md) explains the design at two levels, with diagrams.

[PR #280](https://github.com/aarora79/meru/pull/280), [PR #281](https://github.com/aarora79/meru/pull/281), [PR #282](https://github.com/aarora79/meru/pull/282), [PR #283](https://github.com/aarora79/meru/pull/283)

### Only your user on the socket

`merud` reads the user ID of each process that connects to `merud.sock`, through the operating system's peer credentials, and drops any connection from another user with a warning in `merud.log`. Before it opens the socket, it checks `~/.meru`: it refuses a symlink or a folder another user owns, and closes a folder that others can open. On Windows the check falls back to the folder's permissions.

[PR #286](https://github.com/aarora79/meru/pull/286), closes [#279](https://github.com/aarora79/meru/issues/279)

## What's new

### Honest answers
- When Meru edits a page in your output folder, `read_file` gives the model the page's HTML source, so its links survive the edit. Before, the model read the page as text, lost every link, and wrote the page back with none (#284)
- A web link that no search, page or message in the chat gave gets a note under the answer: the model may have made it up (#284)
- An answer that copies one of Meru's own notices, such as "[These tool calls failed …]", has the copy cut, wherever it sits (#287)
- The claim check now catches "I fixed it in the last answer" and "The page at [link] now has clickable links" when no tool ran (#287)

### Faster turns
- A follow-up the router is unsure of keeps the route of the chat's last turn, in place of the `search+tools` fallback. With a few servers connected, the tool schemas run to about 30,000 tokens, and Ollama keeps one prompt in its cache. After a direct turn, "great job Meru! Yay!!!" re-read 39,844 tokens and waited 45 seconds for its first word; on the same route, Ollama reads only what changed. A follow-up that names a connected tool still gets the tools (#288)
- The thanks rule takes typos and more filler words, so "you did a greewat job meru" gets a quick reply too (#278)
- A long instruction, such as "check my email and send a hello from Meru", no longer starts with a web search for the whole sentence (#287)

## Bug fixes

- `merud.out.log` and `merud.err.log` were readable by other users on the machine. The launchd and systemd files now set a umask of `077`, and `merud` sets both logs to `0600` at startup (#283)
