# Release v0.4.8 - The Mac Installer Opens After a Download

**September 2026**

The Mac installer from v0.4.7 and earlier wouldn't open on a Mac that
downloaded it: macOS called it "damaged". This release fixes that, and puts the
benchmark results in the README and the release notes in the repository.

---

## Upgrading from v0.4.7

### Breaking changes

There are no breaking changes in this release. No config keys were added,
changed or removed, the default models are the same, and `merud`, `meru` and
Meru.app speak the same protocol as in v0.4.7.

### Upgrade instructions

**The one-line installer.** Run it again; it keeps your `config.toml`:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and open "Install Meru.app". Apple hasn't checked Meru, so the first
time macOS refuses: click Done, then Open Anyway in System Settings, Privacy &
Security. The installer leaves your config and memories alone.

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.4.8
go install ./cmd/merud ./cmd/meru
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # or: pkill merud; merud &
```

## Major features

### The Mac installer opens after a download

On a Mac that downloaded the disk image, opening "Install Meru.app" failed with
*"Install Meru" is damaged and can't be opened*, a dialog with no way through.
The Mac that built the image never showed it, because macOS checks only files a
browser marks as downloaded.

- **The cause:** each app carried only the signature Go's linker puts on the
  program inside, with nothing sealing the app's `Info.plist` and resources.
  macOS rejects a downloaded app like that as broken. The installer, the
  Meru.app inside it and the Meru.app zip all had the problem.
- **The fix:** the build now signs each finished app ad hoc and fails if the
  signature doesn't verify. A downloaded copy now gets the usual warning for an
  app Apple hasn't checked, and Open Anyway in System Settings, Privacy &
  Security opens it.
- **The instructions:** macOS 15 no longer lets right-click, Open get past that
  warning, so "Read me first.txt", the README, the landing page and the running
  guide now lead with Open Anyway.

[PR #66](https://github.com/aarora79/meru/pull/66)

### The benchmark in the README

A new section, "How good are the local models?", comes right after the install
steps. It gives the answer model each installer picks for a Mac's memory, with
its pass rate and median times, and links to the full results.

| Mac memory | Answer model | Tasks passed | Time to first token | Time to last token |
|------------|--------------|-------------:|--------------------:|-------------------:|
| under 32 GB | MiniCPM5-2B, the `lite` model | 68% | 11.6 s | 13.1 s |
| 32 to 47 GB | `gemma4:26b-a4b-it-qat` | 80% | 17.6 s | 18.3 s |
| 48 to 63 GB | `qwen3.6:35b` | 89% | 5.6 s | 10.4 s |
| 64 GB or more | `qwen3.6:35b-a3b-mxfp8` | 89% | 4.1 s | 6.5 s |

A test fails the build when a row names a different model from the installers'
table.

[PR #65](https://github.com/aarora79/meru/pull/65)
