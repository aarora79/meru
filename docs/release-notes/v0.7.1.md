# Release v0.7.1 - Questions of fact go to the main model

**November 2026**

With routing on, the fast model now answers only greetings, thanks and requests to reword text you give it. Every question of fact goes to the main model.

---

## Upgrading from v0.7.0

### Breaking changes

There are no breaking changes in this release. A config with `[router] answers = "main"`, the default, behaves exactly as before.

### New config keys

None.

### Upgrade instructions

**The one-line installer on a Mac.** Run it again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and run "Install Meru.app". It leaves your config and memories alone.

**Linux.** Run `install-linux.sh` again; it keeps your config.toml:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install-linux.sh | bash
```

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.7.1
go install ./cmd/merud ./cmd/meru
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # Linux: systemctl --user restart merud
```

Then, on a Mac that reads Apple Notes: macOS drops the Full Disk Access grant
when the `merud` binary changes. In System Settings, open Privacy & Security,
Full Disk Access, and turn `merud` off and on again.

## Bug fixes

- **The fast model stated a wrong fact.** Asked "what is the capital of Japan?" with `answers = "routed"`, the fast model answered "Nara.", while the router was 0.999 sure of the route. Meru's checks for a weak answer catch an answer that stops short. They can't catch a wrong fact. Now a question that ends with a question mark, or opens with a question word such as "what" or "is", or a command such as "tell", "explain" or "list", goes to the main model. The rule tests words, so it adds no time to a turn. (#220)
