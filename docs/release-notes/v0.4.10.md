# Release v0.4.10 - Connectors: Meru Runs Obsidian and Web Search for You

**September 2026**

Meru can now install, start and look after two of its servers for you: the
Obsidian server and SearXNG, the search engine behind web search. Turn one on
in config, and `merud` installs a pinned copy, checks it, and restarts it if it
crashes. `merud` also stays up while Ollama is down and says why, and web
search shows its real state in every client. The README now opens with the
problem Meru solves, and a new explainer shows how connectors work.

---

## Upgrading from v0.4.9

### Breaking changes

There are two breaking changes. Neither needs a change to your config.

**1. `meru mcp --json` prints one object.** `meru mcp --json` and
`meru mcp status --json` now print `{"servers": [...], "connectors": [...]}`.
They used to print the server list as a bare array. A script that read that
array must read `.servers` now:

```sh
meru mcp --json | jq '.servers[]'
```

**2. Going back to v0.4.9 needs a config edit.** v0.4.9's `merud` refuses to
start on a key it doesn't know. If you add a `[connectors.*]` table and then
go back to v0.4.9, take the table out of `config.toml` first.

Update `merud`, `meru` and Meru.app together, as both installers do. The
connector states come from a new request that only v0.4.10's `merud` answers.

Chat files and `meru.db` don't change. A `config.toml` from v0.4.9 loads as it
is. Two things change for you with no edit:

- **Web search follows SearXNG.** `merud` checks `[web] searxng_url` when it
  starts and every minute after. The model gets `web_search` only while
  SearXNG answers, and Settings, `meru mcp` and `/mcp` show why when it
  doesn't. Before, the model got the tool anyway, and the call failed.
- **`merud` waits for Ollama.** It used to exit when Ollama wasn't running or
  was too old. Now it opens its socket, reports "Ollama isn't running at
  http://127.0.0.1:11434.", checks again every 30 seconds, and starts
  answering once Ollama does. `meru ping` succeeds as soon as the socket
  opens.

### New config keys

| Key | Default | What it does |
|-----|---------|--------------|
| `[connectors.searxng] enabled` | no table: `merud` watches `searxng_url` | `true` lets `merud` run SearXNG in the Docker container `meru-searxng` on 127.0.0.1:8888; `false` turns web search off |
| `[connectors.obsidian] enabled` | `false` | `true` lets `merud` install and run the Obsidian server |
| `[connectors.obsidian] vault_path` | none; needed when enabled | The folder that holds your Obsidian notes |
| `[connectors.obsidian] vault_name` | made from the folder's name | A short name the tools use for the vault: a lower-case letter, then lower-case letters, digits, `_` or `-` |

A `config.toml` with no `[connectors.*]` tables leaves Obsidian off and puts
SearXNG in watch mode: `merud` checks the URL and never runs Docker.

### Upgrade instructions

**The one-line installer.** Run it again; it keeps your `config.toml`:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and open "Install Meru.app". The first time, macOS refuses because
Apple hasn't checked Meru: click Done, then Open Anyway in System Settings,
Privacy & Security. The installer leaves your config and memories alone.

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.4.10
go install ./cmd/merud ./cmd/meru
make desktop-app && ditto bin/Meru.app /Applications/Meru.app
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # or: pkill merud; merud &
```

**To try the connectors**, add either table to `~/.meru/config.toml` and
restart `merud`:

```toml
[connectors.obsidian]
enabled    = true
vault_path = "~/Notes/vault"

[connectors.searxng]
enabled = true      # needs Docker
```

`meru mcp` then lists each connector with its state.

If you already run Obsidian through an `[[mcp.servers]]` entry named
`obsidian`, that entry keeps running and the connector shows `set up by hand`.
To switch, take the entry out with `meru mcp remove obsidian`, then turn the
connector on.

## Major features

### Connectors: Meru installs and runs your servers

Until now you set up each MCP server yourself: install its program, start it,
and add an `[[mcp.servers]]` entry. A connector does that part for you. Each
one has a manifest built into `merud` that pins the exact version to install,
names the settings it needs, and says how to check that it works. Obsidian is
the first connector.

- **A pinned install.** With the connector on, `merud` downloads Node 24.21.0,
  checks it against the SHA-256 that nodejs.org publishes, and installs
  obsidian-mcp 2.0.1 with it. Both go under `~/.meru/runtime`, never into your
  system folders. Meru runs the server with its own Node, so it works under
  launchd's short `PATH`. Nothing downloads while every connector is off.
- **Started when needed.** After the install, `merud` starts the server once,
  checks that it lists your vault, and stops it. It starts again on the first
  question that needs your notes, and stops after 10 minutes with no call.
- **Restarted after a crash.** It waits 1, 2, 4, 8 seconds, doubling up to 60,
  then starts the server again. Five crashes in ten minutes stop it as
  `failed`, with the server's last error line. A call that was running when it
  crashed fails, and `merud` never sends it twice.
- **One line of state everywhere.** `meru mcp`, `/mcp` in `meru chat`, the
  connector's card in Meru.app's Settings, and the `about_meru` tool all show
  the same state and sentence: `ok`, `off`, `needs config`, `starting`,
  `failed` or `set up by hand`. For example: "Obsidian is ready. It starts
  when a question needs it." or "Obsidian needs your vault folder."
- **Your own setup wins.** An `[[mcp.servers]]` entry with the connector's name
  runs in its place, so a setup that works today keeps working.
- **Pinned everywhere.** A new policy test fails the build on an unpinned
  version (`latest`, a version range, a container image without a digest) in
  the manifests, installers, scripts and docs.

Google has a manifest but no supervisor yet. Later steps of
[#87](https://github.com/aarora79/meru/issues/87) bring it, with sign-in, a
settings form in both clients, and the installer's hand-off. The new
[connectors explainer](https://github.com/aarora79/meru/blob/v0.4.10/docs/architecture/connectors.md)
covers the whole design and marks each planned part.

[PR #91](https://github.com/aarora79/meru/pull/91),

### Web search that runs and heals itself

SearXNG is the second connector, and the first that runs in a container.

- **Run mode.** With `[connectors.searxng] enabled = true` and the default
  URL, `merud` pulls the SearXNG image by its pinned digest, writes its
  settings under `~/.meru/searxng`, and runs the container `meru-searxng` on
  127.0.0.1:8888. It checks the server every minute and restarts the container
  after 1, 2, 4 and 8 seconds when it fails. Five failures in ten minutes stop
  it as `failed`. Turning the connector off stops the container.
- **Your own SearXNG is safe.** When a SearXNG that `merud` didn't start
  already answers at `searxng_url`, `merud` uses it and never runs, stops or
  removes it. The one from the Mac installer counts as yours.
- **A real check.** `merud` sends an empty query in JSON form. SearXNG refuses
  it with "No query" when JSON works, and with a 403 page when it doesn't, so
  the check tells the two apart and sends nothing off the machine. `/healthz`
  says OK in both cases.
- **Plain sentences for Docker trouble:** "Web search needs Docker, which
  isn't installed." or "Web search can't start: Docker isn't running." The
  next minute's check tries again.
- **Watch mode for everyone else.** With no table, which means every config
  from before this release, `merud` checks the URL and reports what it finds,
  and never runs Docker.
- `meru setup` now prints the `[connectors.searxng]` table in place of the
  Docker Compose recipe.

The Mac installer still starts its own SearXNG container, as before, until a
later step of #87 hands web search to `merud`.

[PR #93](https://github.com/aarora79/meru/pull/93)

### merud waits for Ollama

`merud` used to exit when Ollama wasn't running. Now it opens its socket
first, checks Ollama at once and every 30 seconds, and loads the store and
tools once Ollama answers.

- While Ollama is down or too old, `meru mcp` and the desktop status block
  say why: "Ollama isn't running at http://127.0.0.1:11434." or
  "Ollama 0.12.0 is too old; Meru needs 0.12.11 or later."
- A question gets "Ollama isn't running, so Meru can't answer yet." in place
  of a dead socket.
- Meru.app shows "Waiting for Ollama" and no longer tells you to start
  `merud`.

[PR #93](https://github.com/aarora79/meru/pull/93)
