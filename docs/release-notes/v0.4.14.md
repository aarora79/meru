# Release v0.4.14 - Meru Reads the Pictures It Finds

**October 2026**

An answer model that can see pictures now opens the receipts, tickets and
screenshots that a search finds in your folders, and reads them: ask it to
itemize a trip's receipts and it does. A model that reads text only says so
under its answer and names one of your model sets that can read pictures.

---

## Upgrading from v0.4.13

### Breaking changes

There are no breaking changes. One step turns the new tool on for most people:

**Add `view_image` to your tool list.** Configs written by `meru setup` or the
installer list every built-in tool under `[builtin] tools`, and that list doesn't
grow by itself. Add `"view_image"` to it in `~/.meru/config.toml`, after
`"search_images"`, and restart `merud`:

```toml
tools = ["configure", "datetime", "about_meru", "remember", "write_file",
         "read_file", "list_folder", "grep", "search_files", "search_images",
         "view_image", "web_search", "web_fetch"]
```

A config with no `tools` line gets `view_image` with the other defaults.
[Issue #123](https://github.com/aarora79/meru/issues/123) tracks ending this
step for future tools.

No model to pull, and no re-index.

### New config keys

None. `view_image` joins the default value of `[builtin] tools`.

### Upgrade instructions

**The one-line installer.** Run it again; it keeps your `config.toml`:

```sh
curl -fsSL https://github.com/aarora79/meru/releases/latest/download/install.sh | bash
```

**The Mac installer.** [Download the disk image](https://github.com/aarora79/meru/releases/latest/download/Meru-macos-arm64.dmg),
open it, and open "Install Meru.app". The first time, macOS refuses because
Apple hasn't checked Meru: click Done, then Open Anyway in System Settings,
Privacy & Security. The installer leaves your config and memories alone.

**From source.**

```sh
cd meru
git pull origin main
git checkout v0.4.14
go install ./cmd/merud ./cmd/meru
make desktop-app && ditto bin/Meru.app /Applications/Meru.app
launchctl kickstart -k gui/$(id -u)/com.meru.merud   # or: pkill merud; merud &
```

## Major features

### The answer model reads pictures in your folders

`view_image`, a new built-in tool, shows the answer model a picture from your
`[index]` folders or one you attached, so it can read what the picture says:
a receipt's items, a ticket's price, a screenshot's text, a chart.

- Ask "itemize these receipts and total them by category" after a search found
  them, and the model opens each one and answers from what it reads. In the
  desktop app each one shows as a "Looked at receipt.png" step.
- A picture over 1,536 pixels on its longest side goes to the model scaled down
  to that size. The model's cost grows with the pixels, and eight full-size phone
  photos overflowed the 32,768-token prompt. A 4,000 by 3,000 photo of a bill
  then cost `qwen3.6:35b` 1,756 tokens, and it still read every line.
- One question opens at most eight pictures.
- The picture goes only to Ollama on this machine. The transcript and the
  `tool_calls` log keep a line that names the file, never the picture itself.
- The tool reads under the same rules as `search_images`: only your indexed
  folders and attachments, no secret's name, no link, up to 20 MiB.
- Local models read amounts well but can slip when they add them up. Check a
  total that matters.

[PR #124](https://github.com/aarora79/meru/pull/124)

### A text-only model says so, and names one that can see

Meru offers `view_image` only while the answer model can look at pictures, and
then tells the model in its system prompt that it can read them. A model
without vision, such as MiniCPM5-2B, never sees the tool. When its answer names
a picture, a line under the answer reads, for example: "MiniCPM5-2B reads text
only, so it can't look at these pictures. qwen3.6:35b can: switch to it with
`/model qwen-4bit` in meru chat, or Use for answers in Settings, Models."

Meru picks the suggestion from your own `[[models.sets]]`: the first set whose
model can see pictures and call tools, and that Ollama has pulled. The answer to
an attached picture, for a model without vision, ends with the same line.

[PR #124](https://github.com/aarora79/meru/pull/124)

### Image search weighs the picture over its file name

Searching pictures by words counts a match on a file or folder name a quarter as
much as a match on the picture itself. Names such as `taxi.png`, or a folder
named for a trip, matched questions about other pictures from the same trip. On
75 test questions over 25 pictures, the right picture came first for 27 questions
where it came first for 19 before, and in the top five for 47 where it was 38.

[PR #121](https://github.com/aarora79/meru/pull/121)

## What's new

- The line under an image search result no longer tells the model it can't see
  the picture, which kept a model with vision from opening it (#124).
- An evaluation of image search, behind the `integration` build tag, reports how
  often a description finds its picture first and in the top five (#121).
- [How do I find an image?](https://github.com/aarora79/meru/blob/v0.4.14/docs/faq/find-images.md)
  gains a section on reading what a picture says (#124).
