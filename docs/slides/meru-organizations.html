The question

The data AI helps with most is the data a company least wants to send out

  • A hosted assistant reads each question on its provider's servers, with the documents, mail and records attached to it.
  • Each one is a data processor to assess, contract with and monitor, and its terms can change.
  • Meru takes the other path. Open-weight models run on the employee's own machine, beside the data, and no model provider is in the path.

What people use

Meru.app, a desktop app on each person's Mac

  • Ask across work data: documents, mail and calendar, the web, and company systems such as SharePoint, Confluence or Salesforce through MCP servers the company allows.
  • Attach files and pictures, or speak the question.
  • Approve on a card any tool call that sends, deletes or changes, before it runs.
  • Settings for connections, folders, skills and models, and a Usage screen.

The app talks to merud, the program that runs the models through a local model server on 127.0.0.1, Ollama today, and owns the data; meru chat in a terminal and meru run --json for scripts talk to the same merud. The code has no path to a cloud model, and a test in CI fails the build if one appears. Apache License 2.0, written in Go, 19 releases since the first commit on 23 September 2026. macOS on Apple silicon first; Linux supported; Windows untested.

Data flow

What leaves the machine, and what doesn't

DataWhere it goes
Questions and answersNowhere. The models run in a model server on the same machine.
Files and documentsIndexed into a SQLite file on the machine; read live, never copied out.
Telemetry, crash reports, update checksNone. Metrics go to a Prometheus the company runs on the same machine.
Web searchesThe search words go to the engines the company's own SearXNG asks.
Web pagesPublic addresses only. Meru asks first for an address no search or question gave, unless the user trusted that website.
Mail and calendarRead through the user's own account, when they connect it; Google today.
Company systemsSharePoint, Confluence, Salesforce and the like, through an MCP server the company allows, tool by tool. Meru reaches that server and nothing else.

Controls

Controls a security team can check

ControlHow Meru does it
ToolsDeny by default. A new tool server contributes nothing until config names its tools. Each tool is Off, Ask or Allow; sending, deleting or changing asks every time.
NetworkConnects only to its own machine, except to servers marked remote and to public pages it reads; refuses private addresses at connect time.
SecretsAPI keys in one file only the user can read; kept out of the model, the logs and the history.
Supply chainEvery program Meru installs is pinned by version and SHA-256 or image digest; CI signs a record of how its speech server was built.
EnforcementPolicy tests in CI fail the build on a cloud model, a second path to a tool, or a forbidden import.

Audit

Every tool call leaves a record on the machine

  • One path for every tool call. MCP servers, other agents, local commands and built-in tools all go through dispatch, which checks the allowlist, asks for approval, and logs the call.
  • Two records. A tool_calls row with the tool, time, duration, outcome and approval, and the session's transcript, a plain JSON Lines file.
  • Incognito keeps the audit row. An incognito chat keeps no transcript, and its rows keep no arguments or results, but each call is still counted.
  • Metrics and traces in OpenTelemetry, to a collector on the same machine only. Prompt and answer text stay out of traces unless config turns capture on.

Sizing

What the hardware has to hold

Memory, as the model server loaded it

  • qwen3.6:35b with a 262,144-token window: 28.8 GB
  • The same model at 32,768 tokens: 23.4 GB
  • MiniCPM5-2B, the fast model: 2.8 GB
  • The search model: 0.7 GB

What follows

  • A 64 GB Apple silicon Mac runs the full set with room to spare.
  • Under 32 GB, Meru runs the 2B model and passes fewer questions.
  • Meru sizes each answer model's window to fit an eighth of memory.
  • The answer model wrote 84 to 93 tokens a second on an M4 Max.

Rollout today

What it takes to put Meru on a machine

  • A Mac installer on a disk image sets up the model server, web search, folders and merud in eleven steps in a window. A one-line installer does the same in a terminal.
  • One config file per person, ~/.meru/config.toml: the models, the folders, the tools and what each may do.
  • Updates are manual. Meru never checks for them, so the company decides when a new version reaches each machine.
  • Files are the source of truth. The database can be deleted and rebuilt from the transcripts, memories and config.

Gaps

What Meru does not do today

For a fleet

  • No central console to push config or policy
  • No single sign-on or directory link
  • Ready-made connectors only for Google and web search; SharePoint, Confluence or Salesforce need an MCP server
  • No central log collection: metrics and traces stay on the machine by design
  • One person per machine; no shared server

For the project

  • Pre-alpha, v0.4.19
  • One maintainer; the first outside contribution merged in October 2026
  • Scheduled jobs come in v0.5
  • Windows builds, untested

For a platform provider

What a managed offering around Meru would have to add

Fleet setup and config

Install, update and push config.toml with each team's allowlists, as the company's device management already does for other programs.

A model catalog

Open-weight models chosen per hardware tier, pinned by digest and served from a mirror the company controls.

Hardware

Apple silicon Macs or GPU machines with enough memory per person, on desks or in the company's own account; the boundary holds wherever the machine is.

Connectors and audit

MCP servers for the company's own systems, and a collector the company runs on each machine to gather the audit rows Meru keeps there.

The Apache License 2.0 allows this. Meru's core stays local by design: no cloud model, no telemetry, deny by default.
