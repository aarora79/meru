# URLs a shipped Go string literal may contain even though their host isn't
# loopback. TestNoNonLoopbackURLLiterals reads this file.
#
# Only documentation links belong here: a URL that Meru prints for a person to
# open, such as a help link in an error message. Meru must never fetch one.
# There are two exceptions, each listed below with its reason: the Mac
# installer's download of Ollama.app, which it fetches only when the user
# presses Continue on a screen that shows the URL, and the pinned Node, uv
# and chrome-headless-shell archives merud downloads for connectors and for
# web_fetch's page reader, each checked against its SHA-256 before use. Links in comments don't need an entry, because the
# test reads string literals only.
#
# One URL prefix per line. A literal URL passes when it starts with an entry.
# Give every entry a reason after "#", for the reviewer who has to accept it.
#
# Hosts reserved for examples (example.com, example.net, example.org, and any
# name ending in .example, .test, .invalid or .localhost) always pass, because
# nothing answers on them.

# meru setup prints where to get Ollama when it isn't running.
https://ollama.com/download      # Ollama's download page, printed by meru setup
https://ollama.com/install.sh    # the Linux install command meru setup prints

# meru setup prints the commands that start SearXNG, for web search, when it
# doesn't answer. The user runs them; Meru never fetches these files.
https://raw.githubusercontent.com/searxng/searxng/master/container/  # SearXNG's compose file and .env example

# The MCP server catalog (internal/catalog) prints each server's upstream
# page and where to get what it needs. meru prints these links for the user;
# merud never fetches them.
https://github.com/modelcontextprotocol/servers/tree/main/src/fetch  # the fetch server's docs
https://github.com/taylorwilsdon/google_workspace_mcp        # the Google Workspace server's docs
https://github.com/MarkusPfundstein/mcp-obsidian             # the Obsidian server's docs
https://github.com/modelcontextprotocol/servers/tree/main/src/filesystem  # the filesystem server's docs
https://github.com/CursorTouch/Windows-MCP                   # the Windows server's docs
https://workspacemcp.com/quick-start                         # how to make a Google OAuth client
https://docs.astral.sh/uv/getting-started/installation/      # how to install uv, which runs uvx

# The desktop app's About section and meru chat's /about box link to the
# project on GitHub (internal/about). The user clicks them and the system
# browser opens them; neither client fetches them.
https://github.com/aarora79/meru  # the source, the design and new issues

# The Mac installer (internal/installer). Every link opens in the user's
# browser when they click it, except Ollama-darwin.zip.
https://ollama.com/download/Ollama-darwin.zip  # FETCHED by the installer, once, after the user presses Continue on a Mac with no Homebrew; the screen shows this URL first
https://www.docker.com/products/docker-desktop/  # where to get Docker, for web search; the Web search screen links it
https://console.cloud.google.com/  # the Google Cloud pages the Google screens link, steps 1 to 5 of docs/google-setup.md
https://github.com/aarora79/meru/blob/main/docs/google-setup.md  # the full Google guide, linked from the Google screens
http://www.apple.com/DTDs/PropertyList-1.0.dtd  # the DOCTYPE line of a launchd plist; launchd never fetches it

# The connector runtimes (internal/connectors/runtimes.go). merud FETCHES
# these archives the first time a connector needs Node or uv, and runs
# nothing from one until its SHA-256 matches the pin. Each prefix names
# one pinned release, so a new pin needs a new entry and a reviewer.
https://nodejs.org/dist/v24.21.0/  # FETCHED by merud: Node 24.21.0, for npm connectors such as obsidian
https://github.com/astral-sh/uv/releases/download/0.12.21/  # FETCHED by merud: uv 0.12.21, for pip connectors such as google
https://storage.googleapis.com/chrome-for-testing-public/154.0.8037.92/  # FETCHED by merud: chrome-headless-shell 154.0.8037.92, web_fetch's page reader for pages that need JavaScript
